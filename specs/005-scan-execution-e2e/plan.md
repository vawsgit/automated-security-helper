# Implementation Plan: Scan Execution End-to-End

**Branch**: `005-scan-execution-e2e` | **Date**: 2026-03-16 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/005-scan-execution-e2e/spec.md`

## Summary

Wire the complete scan execution flow: user triggers a scan from any entry point (command palette, context menu, sidebar, findings panel), the extension spawns the ASH CLI via the existing `ScannerService`, reports progress to WebViews in real time, parses SARIF results, stores findings in the database, and pushes updated state back to all UI surfaces. Replaces all mock data and placeholder implementations with real database-backed operations.

## Technical Context

**Language/Version**: TypeScript (strict mode, ES2022 target, Node16 modules)
**Primary Dependencies**: VS Code API, React 19, PGLite + Prisma ORM, ScannerService (Spec 004)
**Storage**: PGLite (WASM PostgreSQL) via Prisma — existing, no changes
**Testing**: Mocha (unit, Node.js) + `@vscode/test-electron` (integration), sinon
**Target Platform**: VS Code extension (desktop, all platforms)
**Project Type**: VS Code extension + React WebView
**Performance Goals**: Progress visible within 2s of scan start, 1s update interval
**Constraints**: Single-scan constraint (enforced by ScannerService), extension host owns all state
**Scale/Scope**: Single user, single workspace, 6 files modified in vsix/, 2 files modified in webview/, 1 new file

## Implementation Phases

### Phase 1: Message Protocol & Mappers (Foundation)

Update the message types in both packages and create the Prisma-to-view mapper functions. This unblocks all subsequent work.

**Files**: `vsix/src/models/messages.ts`, `webview/src/types/messages.ts`, `vsix/src/models/mappers.ts`

### Phase 2: Provider Wiring (Core)

Replace mock data in all three providers with real database queries using the mappers. Add new methods for progress broadcasting and state updates.

**Files**: `findingsPanelManager.ts`, `sidebarWebviewProvider.ts`, `scanTreeProvider.ts`

### Phase 3: Command & Extension Wiring (Integration)

Replace mock scan commands with real ScannerService calls. Wire dependency injection through `extension.ts`. Implement the scan target picker and shared scan execution helper.

**Files**: `scanCommands.ts`, `commands/index.ts`, `extension.ts`

### Phase 4: WebView Reducer (UI)

Add the `scanProgress` message handler to the App.tsx reducer so the WebView responds to progress updates during scanning.

**Files**: `webview/src/App.tsx`

### Phase 5: Polish

Compile, lint, and verify all changes work together. Remove unused mock imports.
