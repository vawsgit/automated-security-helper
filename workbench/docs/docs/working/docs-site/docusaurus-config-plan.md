# Docusaurus Configuration Implementation Plan

## 1. Executive Summary

Configure the greenfield Docusaurus v3.9.2 site from stock template to a production-ready, self-organizing documentation system for the ASH Workbench project. The site will serve three audiences via separate navbar sections (User Docs, Developer Docs, Working), use autogenerated sidebars for zero-config page addition, support Mermaid diagrams, and exclude working docs from production builds via environment variable.

**Key decisions:**
- Single docs plugin with three autogenerated sidebars (not multi-instance)
- Simple landing page homepage (no Hero banner)
- `DOCUSAURUS_ENV` environment variable to filter working docs from production
- Mermaid enabled as the preferred diagram format
- Blog disabled

## 2. What Will Be Done

- Replace all template placeholder values in `docusaurus.config.ts` (title, URL, org, editUrl, etc.)
- Reconfigure sidebars from single `tutorialSidebar` to three autogenerated sidebars
- Update navbar with three doc section links (User Docs, Developer Docs, Working)
- Update footer with project-relevant links
- Disable the blog plugin
- Install and enable `@docusaurus/theme-mermaid`
- Replace the stock homepage with a simple landing page describing the three doc sections
- Remove all template artifacts (intro.md, markdown-page.md, stock illustrations)
- Create seed README.md and `_category_.json` files in each content section
- Add environment-variable-based filtering to exclude working docs from production builds
- Create a `_category_.json` for the existing `working/docs/` subdirectory

## 3. What Will NOT Be Done

- Custom CSS branding / color scheme changes (deferred)
- GitHub Pages deployment pipeline setup (deferred)
- Creating actual documentation content beyond seed overview pages
- Setting the production `url` and `baseUrl` for GitHub Pages (deferred until deployment)
- Versioned docs
- Search plugin integration
- i18n / localization

### Phase 4: Homepage

**Status: Not Completed**

Replace the stock Docusaurus homepage with a simple landing page describing the three doc sections.

**Step 4.1: Rewrite `src/pages/index.tsx`**

Replace with a simple page containing:
- Site title and tagline from `siteConfig`
- Brief description of the doc site's purpose
- Three card-style links to User Docs, Developer Docs, and Working sections
- No SVG illustrations; text-only cards with section title and brief description

```tsx
import type {ReactNode} from 'react';
import clsx from 'clsx';
import Link from '@docusaurus/Link';
import useDocusaurusContext from '@docusaurus/useDocusaurusContext';
import Layout from '@theme/Layout';
import Heading from '@theme/Heading';

import styles from './index.module.css';

const sections = [
  {
    title: 'User Docs',
    to: '/docs/user-docs/',
    description:
      'Learn how to use the ASH Workbench to scan and analyze your code for security issues.',
  },
  {
    title: 'Developer Docs',
    to: '/docs/developer-docs/',
    description:
      'Architecture, implementation guides, and reference for contributors.',
  },
  {
    title: 'Working',
    to: '/docs/working/',
    description:
      'Research notes, plans, and in-progress documentation.',
  },
];

export default function Home(): ReactNode {
  const {siteConfig} = useDocusaurusContext();
  return (
    <Layout description="ASH Workbench documentation">
      <header className={styles.heroBanner}>
        <div className="container">
          <Heading as="h1">{siteConfig.title}</Heading>
          <p className={styles.subtitle}>{siteConfig.tagline}</p>
        </div>
      </header>
      <main className="container margin-vert--lg">
        <div className={clsx('row', styles.sections)}>
          {sections.map(({title, to, description}) => (
            <div key={title} className="col col--4">
              <div className={styles.card}>
                <Heading as="h3">
                  <Link to={to}>{title}</Link>
                </Heading>
                <p>{description}</p>
              </div>
            </div>
          ))}
        </div>
      </main>
    </Layout>
  );
}
```

### Phase 5: Working Docs Production Filtering

**Status: Not Completed**

Use an environment variable to conditionally exclude working docs from production builds.

**Step 5.1: Add conditional sidebar in `sidebars.ts`**

```ts
import type {SidebarsConfig} from '@docusaurus/plugin-content-docs';

const isProduction = process.env.DOCUSAURUS_ENV === 'production';

const sidebars: SidebarsConfig = {
  userDocsSidebar: [{type: 'autogenerated', dirName: 'user-docs'}],
  developerDocsSidebar: [{type: 'autogenerated', dirName: 'developer-docs'}],
  ...(isProduction ? {} : {
    workingSidebar: [{type: 'autogenerated', dirName: 'working'}],
  }),
};

export default sidebars;
```

**Step 5.2: Add conditional navbar item in `docusaurus.config.ts`**

Wrap the Working navbar item conditionally:

```ts
const isProduction = process.env.DOCUSAURUS_ENV === 'production';

// In navbar.items array:
items: [
  {
    type: 'docSidebar',
    sidebarId: 'userDocsSidebar',
    position: 'left',
    label: 'User Docs',
  },
  {
    type: 'docSidebar',
    sidebarId: 'developerDocsSidebar',
    position: 'left',
    label: 'Developer Docs',
  },
  ...(isProduction ? [] : [{
    type: 'docSidebar' as const,
    sidebarId: 'workingSidebar',
    position: 'left' as const,
    label: 'Working',
  }]),
  {
    href: 'https://github.com/awslabs/automated-security-helper',
    label: 'GitHub',
    position: 'right' as const,
  },
],
```

**Step 5.3: Add conditional `excludePattern` in docs plugin**

To prevent build errors from orphaned working docs when the sidebar is excluded:

```ts
docs: {
  sidebarPath: './sidebars.ts',
  editUrl: '...',
  ...(isProduction ? { exclude: ['working/**'] } : {}),
},
```

**Step 5.4: Conditionally filter Working from homepage sections**

In `src/pages/index.tsx`, filter the sections array:

```ts
const allSections = [/* ... all three ... */];
const isProduction = process.env.DOCUSAURUS_ENV === 'production';
const sections = isProduction
  ? allSections.filter(s => s.title !== 'Working')
  : allSections;
```

Note: `process.env.DOCUSAURUS_ENV` works in Node.js config files. For client-side React components (`index.tsx`), use Docusaurus's `customFields` to pass it through:

```ts
// docusaurus.config.ts
const config: Config = {
  // ...
  customFields: {
    isProduction,
  },
};
```

Then in `index.tsx`:

```ts
import useDocusaurusContext from '@docusaurus/useDocusaurusContext';

const {siteConfig} = useDocusaurusContext();
const isProduction = siteConfig.customFields?.isProduction as boolean;
```

## 7. KISS Opportunities

### Defer `_category_.json` for top-level sections
**Impact:** Reduces files created
The `_category_.json` files at `user-docs/` and `developer-docs/` root level are not strictly needed since each has its own sidebar via `dirName`. Only create them for subdirectories within sections. The top-level label is controlled by the navbar item.

### Skip footer link customization for now
**Impact:** Minor
The footer links to `/docs/user-docs/` and `/docs/developer-docs/` depend on those paths resolving correctly. With only seed README.md files, these links work but are thin. Could use a minimal footer and expand later.
**Decision:** Include the footer update since it's trivial and removes the template links.
