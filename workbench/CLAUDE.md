# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ASH Workbench is a VS Code extension for the Automated Security Helper (ASH) project. The repository is a monorepo with two subprojects sharing a root workspace.

## Repository Structure

```
workbench/
  vsix/           # VS Code extension (TypeScript)
  docs/           # Docusaurus v3 documentation site
  .claude/        # Claude Code commands and skills
  .specify/       # Project specification templates and scripts
```

## VS Code Extension (`vsix/`)

### Build & Run

```bash
cd vsix
npm run compile       # TypeScript compile to out/
npm run watch         # Compile in watch mode
npm run lint          # ESLint (flat config, typescript-eslint)
npm run test          # Run tests via @vscode/test-cli
npm run pretest       # Compile + lint (runs before test)
```

- Source: `vsix/src/extension.ts` (entry point, exports `activate`/`deactivate`)
- Tests: `vsix/src/test/` (Mocha, runs in VS Code test electron)
- Output: `vsix/out/` (compiled JS + sourcemaps)
- TypeScript: strict mode, ES2022 target, Node16 modules

### Extension Details

- Extension ID: `ash-workbench`
- Activation: on-demand (command-triggered)
- VS Code engine: `^1.110.0`
- Commands registered in `package.json` under `contributes.commands`

## Documentation Site (`docs/`)

Docusaurus v3.9.2 with React 19 and Mermaid support.

### Build & Run

```bash
cd docs
npm run start         # Dev server with hot reload (localhost:3000)
npm run build         # Production build to build/
npm run serve         # Serve production build locally
npm run clear         # Clear .docusaurus cache (do this after config changes)
```

### Architecture

Single docs plugin with three autogenerated sidebars. New pages self-organize — adding a `.md` file with `title` frontmatter is all that's needed.

- **`docs/docs/user-docs/`** → "User Docs" navbar/sidebar — end-user documentation
- **`docs/docs/developer-docs/`** → "Developer Docs" navbar/sidebar — contributor/developer documentation
- **`docs/docs/working/`** → "Working" navbar/sidebar — ephemeral research, plans, AI working docs

Working docs are excluded from production builds via `DOCUSAURUS_ENV=production`.

### Key Conventions

- **Never modify `sidebars.ts` or `docusaurus.config.ts`** to add docs — autogenerated sidebars handle it
- **`README.md`** in any directory becomes the category index ("Overview" page)
- **`_category_.json`** required in every new subdirectory (sets label, position)
- **Frontmatter**: every `.md` file needs at minimum `title:`
- **Mermaid** is the preferred diagram format (enabled via `@docusaurus/theme-mermaid`)
- **File names**: kebab-case only (`system-overview.md`)
- **Cross-links**: use relative file paths (`../user-docs/feature.md`), not absolute URLs
- Consolidate when a flat directory exceeds 6-8 files

### Production Build

```bash
DOCUSAURUS_ENV=production npm run build   # Excludes working/ docs
npm run build                              # Includes all sections
```

## Claude Code Skills

Two custom skills exist in `.claude/skills/`:

- **`dev-docs`** — triggered by requests to write developer documentation. Searches existing docs first, then creates/updates/consolidates in `docs/docs/developer-docs/`.
- **`user-docs`** — triggered by requests to write user documentation. Same search-first pattern, targets `docs/docs/user-docs/`.

Both skills enforce a "search before write" convention to prevent duplicate documentation.

## Lint & Style

- VS Code extension: ESLint flat config (`vsix/eslint.config.mjs`) — `typescript-eslint` parser, camelCase/PascalCase imports, curly braces, strict equality, semicolons
- Docs site: standard Docusaurus/Prettier conventions
